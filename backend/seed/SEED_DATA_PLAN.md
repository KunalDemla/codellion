# Seed-data plan

MVP target: 20 reviewed questions, 10–20 accepted answers each, distributed across programming, algorithms, cybersecurity, cryptography, networking, operating systems, databases, computer architecture, software engineering and computing history.

For each answer record: canonical name, aliases, rarity tier, points, short explanation, source URL, license/attribution, and review status.

Pipeline:
1. Discover candidate concepts/entities using Wikidata SPARQL.
2. Verify facts using official documentation, standards, textbooks and reputable educational sources.
3. Write original prompts and define a bounded answer class.
4. Curate canonical answers and aliases.
5. Human-review correctness, ambiguity, duplicates and rarity.
6. Store source and license provenance.
7. Later use anonymized player answer frequency as an additional rarity signal.

Do not blindly import community Q&A text. Check each dataset's exact license and attribution/share-alike requirements. Do not assume every record has the same license.

The included questions are development fixtures, not final rarity judgments.
